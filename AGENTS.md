# Agentic Design Tutorial Repository — Version 2

This repository is an intro/tutorial project for running the front end of a
design thinking sprint with agentic software practices. It turns
`docs/brief.md`, supporting documents, and the ordered resources in
`exercises/` into evidence-tracked framing artifacts for later ideation and
prototyping. Its objective is to help teams develop and revise their own problem
understanding through attributable evidence, independent interpretations, and
structured challenge, while teaching the fundamental agentic building blocks.

## Repository Contract

- Treat `docs/brief.md` as the CLI's primary challenge input. Web projects use
  their explicitly supplied private briefs.
- Treat numbered Markdown files under `exercises/` as the canonical ordered exercise
  definitions. The numeric prefix controls execution order, but each exercise
  must be analyzed as an independent action before synthesis.
- Treat HTML and PDF files under `exercises/` as optional local source
  material. They are ignored by Git and must not be required by the runtime.
- Assign human evidence explicitly per run through CLI `--evidence` arguments or
  web selections. The runtime reads UTF-8 text snapshots; photos require
  human-authored captions or observations. Never scan evidence directories or
  invent missing field data.
- Treat `outputs/v2/ledger/events.jsonl` as append-only provenance storage. Never rewrite or
  delete claims, evidence, or conflict history.
- Keep ideation and prototyping out of scope. The system may prepare inputs for
  those phases but must not propose final solutions as if they were validated.

## Required Operating Principles

- Use one analyst by default. It receives only the selected exercise, assigned
  evidence snapshots, and reviewed prior claims.
- Freeze an independent human interpretation before each new framing run; never
  send it to either model or treat it as factual evidence.
- Require a human comparison, revised or defended frame, unresolved disagreement,
  and next investigation before applying a framing review.
- Use the optional critic only as a distinct audit contract. It cannot create
  claims, approve them, or write the ledger.
- Preserve evidence provenance. Every takeaway must point to source document,
  exercise, agent, confidence, validation status, and graph claim IDs.
- Record structured logs for model steps, budgets, retries, checkpoints,
  warnings, and validation decisions.
- Do not log hidden chain-of-thought. Log concise public rationale,
  assumptions, evidence references, and decision summaries.
- Prefer explicit schemas and small modules over broad, multi-mode functions.
- Require repeatable evaluation evidence before adding agents or tools.
- Handle inconsistency as design material unless stronger evidence invalidates a
  claim. Deprecated claims remain in the graph with invalidation edges.
- Corrections append new events; they never alter applied worksheets or ledger
  history. Invalid premises block dependent claims from context and reports.
- Separate exact passage validity from semantic grounding and human reasoning
  quality. Do not claim learning benefits from structural scores or a fictional
  demonstration. Measure repeated and unassisted human investigation explicitly.

## Expected Final Artifacts

The final compiler should produce:

- framed challenge with named audience and correct altitude;
- defined audiences and role distinctions;
- stakeholder persona mappings with pains, gains, and jobs to be done;
- landscape and constraint facts;
- opportunity reframings, usually in How Might We form;
- project plan for later ideation and prototyping phases.

## Local Configuration

Use `config/project.yaml` as the strictly typed configuration source. Use the
analyst and critic profiles in `agents/`, and the repo-local skill in
`skills/design-sprint-agentic/`. Version 2 has no MCP runtime.

## Tests and Model Changes

- Keep core code in `agentic_dt/` and optional host adapters in `extensions/`;
  keep offline unit/integration tests in `tests/local/` and real service tests in
  `tests/live/`.
- Ordinary `pytest` must stay offline, even when credentials are present. Live
  tests require `--run-live`, `--live-budget-usd`, and `OPENAI_API_KEY`.
- Live tests use explicitly fictional inputs, isolated output/ledger paths, and
  no automatic human approval. Do not execute them without spending authority.
- Update model defaults, reasoning settings, and price estimates together.
  Preserve historical manifests and requests; never silently migrate a resume.
- Treat `*.egg-info/` as generated packaging metadata, not project source. It may
  be regenerated by editable installation and is already ignored by Git.
